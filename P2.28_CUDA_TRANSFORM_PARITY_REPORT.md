## 3. CPU and GPU paths

### CPU reference

The CPU side used the unchanged production `CPUTransformBackend`, which delegates to the unchanged `apply_shot_transform()` path with:

- SDR transfer: BT.709 / BT.1886;
- HDR transfer: SMPTE2084/PQ;
- peak: `10000.0` nits;
- BT.709 to BT.2020 matrix unchanged;
- BT.2020 luminance weights `0.2627, 0.6780, 0.0593`;
- P2.27.2's preserved 64-point luminance curve;
- production 65,536-entry curve LUT;
- existing low-end bridge and true-black handling;
- existing PQ OETF square-root-spaced LUT;
- identity color matrix and saturation `1.0`.

### GPU candidate

The GPU side used the existing opt-in P2.20 `GPUTransformBackend` without modification. It used the existing host NumPy to CuPy to host NumPy boundary and float64 device buffers. No `FallbackTransformBackend` was used, so a CPU fallback could not silently pass the test.

The host curve LUT generated for CPU and GPU was compared element-for-element:

```text
cpu_gpu_host_curve_lut_equal = true
curve LUT entries = 65536
PQ LUT entries = 65536
curve LUT dtype = float64
PQ LUT dtype = float64
```

The workload was the concatenation of the P2.27.2 top and bottom extensions:

```text
sdr_frame[0:280, :, :] + sdr_frame[1880:2160, :, :]
shape = (560, 3840, 3)
dtype = float64
```

## 12. Limitations and non-goals

1. This probe validates the mathematical transform boundary only. It does not validate production composition integration, FFmpeg AVFrame ownership, CUDA frame interop, NVDEC-to-CuPy transfer, NVENC integration, or a native FFmpeg CUDA filter.
2. The existing GPU backend's host NumPy to CuPy to host NumPy boundary was intentionally retained. No device-frame-to-NVENC path was attempted.
3. The HDR overlap check uses the existing architecture in which the overlap is direct HDR placement and is not sent through the transform backend. It proves exact CPU/GPU composite overlap equality, not a GPU transform of HDR overlap.
4. Shadow and jacket labels are separate report categories but use the same established physical ROI coordinates (`1900:2050,1500:2500`).
5. P99/P99.9 for the very large all-frame populations use the deterministic reservoir method documented in the JSON; max/mean/RMSE are exact streaming values.
6. The P2.27.2 shadow distribution remains a diagnostic observation. The `0.005`-nits repetition above 5% is not interpreted as proof of an actual visual plateau and is not a CUDA parity failure.
7. The performance results are not full-renderer results and must not be used as a final production throughput claim.
