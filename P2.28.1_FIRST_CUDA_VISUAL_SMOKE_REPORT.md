## 10. Warnings and issues

1. The HDR source decoder emitted an input-container warning, `Unsupported encoding type`, for non-video material streams. The selected video decoded successfully, returned code `0`, and produced all 120 frames.
2. NVENC emitted `Incompatible pixel format 'yuv420p10le' ... auto-selecting format 'p010le'`. The final stream was nevertheless validated by ffprobe as `yuv420p10le` with the required HDR10 signaling.
3. The geometry confidence remains the preserved P2.27.2 value `0.9155`; no geometry correction was applied.
4. The shadow diagnostic remains `0.005 nits / 5.134461111%`. It was not used as a CUDA smoke failure, consistent with P2.27.3.
5. No PNG/TIFF snapshot was generated. The isolated FFmpeg build does not provide a PNG path in the established snapshot workflow. Full-resolution float64 NPY and RGB48LE snapshots were preserved instead, and the HDR10 MKV is the viewable artifact.
6. The output is a real HDR10 NVENC deliverable at the established P2.27.2 CQ18 settings; the unencoded RGB48LE snapshots preserve the CUDA frame values before lossy video encoding.
