# P2.18: Post-Optimization Transform Profiling Report

## Executive Summary

This was an observational profiling task only. No production optimization was implemented, no production tests were modified, no video was rendered, and no commit/push was performed.

Current pipeline measured:

- P2.15 luminance curve LUT 65k
- P2.17 PQ OETF sqrt-spaced LUT 65k + linear interpolation
- ROI: `560 × 3840 = 2,150,400` pixels
- Input: same `np.random.default_rng(217)` / float64 ROI configuration used by P2.17
- Stage timing: 10 measured runs after 2 warmups

### Main result

| Rank | Stage | Median | Share of profiled total |
|-----:|-------|-------:|------------------------:|
| 1 | PQ OETF sqrt-LUT | 145.56 ms | **38.77%** |
| 2 | BT.1886 linearization | 105.46 ms | **28.09%** |
| 3 | Luminance curve LUT | 32.33 ms | **8.61%** |
| 4 | RGB × luminance ratio | 24.43 ms | **6.51%** |
| 5 | BT.2020 luminance | 19.84 ms | **5.28%** |
| 6 | BT.709 → BT.2020 matrix | 17.60 ms | **4.69%** |

The current dominant costs are therefore the PQ OETF implementation and per-channel BT.1886 EOTF. No optimization was applied to either stage in P2.18.

## 1. Profiled Production Path

The profiler reproduced the current `apply_shot_transform()` operation order:

```text
A  input preparation
B  BT.1886 linearization
C  BT.709 → BT.2020 matrix + non-negative clamp
D  BT.2020 luminance
E  luminance curve LUT
F  safe ratio
G  RGB × ratio
H  RGB maximum clamp
K  identity color/saturation branch checks
I  PQ OETF sqrt-LUT
J  final output clip
```

The curve LUT was built before the measured runs and reused. It was not rebuilt inside the frame loop.

### Source of the PQ-related memory peak

The current P2.17 `pq_oetf_sqrt_lut()` path creates full-ROI temporary arrays for:

- normalized input
- square-root lookup coordinate
- integer lower index
- interpolation fraction
- interpolation arithmetic/result

Additionally, `delinearize()` evaluates `linear * peak_nits`, which is another full RGB temporary before entering the LUT function.

The measured PQ stage peak delta was **361.27 MB** for this ROI. This is the principal source of the high peak allocation observed after P2.17.

## 5. Allocation / Copy Audit

No source was changed. The following is a static audit of the current code.

### A — Input preparation

- `apply_shot_transform()` has no explicit dtype conversion.
- The profiler's `np.asarray(frame)` returned the same float64 ndarray.
- No `astype()` or `np.copy()` occurs here.
- No full-frame copy was created by input preparation in this test.

### B — BT.1886 linearization

`linearize()` → `bt1886_eotf()` performs:

```python
signal = np.clip(signal, 0.0, 1.0)
return np.power(signal, 2.4)
```

For the ROI, this creates full RGB arrays of approximately 49.22 MiB each. The clip input/output and power output can overlap in lifetime.

### C — BT.709 → BT.2020

```python
linear_709.reshape(-1, 3)       # view, no data copy
@ _M_709_TO_2020.T              # new full RGB array
.reshape(shape)                 # view
np.maximum(..., 0.0)            # new full RGB array
```

The matrix multiplication is the only compute-heavy matrix operation. The reshape operations are views. The maximum clamp creates a second full RGB array.

### D — BT.2020 luminance

The weighted channel expression creates a full 2D float64 luminance result. Channel slices are views, while arithmetic temporaries are short-lived full 2D arrays.

### E — Luminance curve LUT

The P2.15 implementation creates/uses:

- `np.zeros_like(sdr_luminance)` result
- bridge and fitted boolean masks
- fitted luminance selection array
- normalized LUT coordinate `t`
- integer LUT index array
- LUT output selection
- clipping/indexing temporaries

The prebuilt 65k curve LUT itself is not rebuilt per frame.

### F — Safe ratio

```python
safe_mask = lum > 1e-6
ratio = np.ones_like(lum)
np.divide(lum_mapped, lum, out=ratio, where=safe_mask)
```

Creates one full boolean mask and one full float64 ratio array. `np.divide(..., out=ratio)` avoids a separate output allocation for the division result.

### G — RGB × ratio

```python
linear = linear * ratio[..., np.newaxis]
```

The broadcasted ratio is a view, but multiplication creates a new full RGB float64 array of 49.22 MiB.

### H — Maximum clamp

```python
linear = np.maximum(linear, 0.0)
```

Creates another full RGB output. The preceding RGB product is released after assignment, but both exist during the operation's peak.

### K — Other operations

The identity color-matrix branch creates only a 3×3 array and an identity comparison array. Saturation is skipped for the baseline transform (`saturation == 1.0`). These are not ROI-sized allocations.

### I — PQ OETF sqrt-LUT

The current implementation uses full-ROI arrays for normalization, square root, lookup position, integer index, fraction, and interpolation. This is the largest transient-memory stage.

### J — Final output

```python
np.clip(hdr_signal, 0.0, 1.0)
```

Creates one final full RGB float64 array of 49.22 MiB.

## 6. Scaling Check

Each size used 10 measured full `apply_shot_transform()` runs after warmup. The same curve LUT was reused.

| Height×width | Pixels | Median ms | Min ms | Max ms | ms / million pixels |
|--------------|-------:|----------:|-------:|-------:|--------------------:|
| 540×960 | 518,400 | 81.81 | 81.29 | 85.88 | 157.82 |
| 1080×1920 | 2,073,600 | 356.58 | 343.32 | 366.11 | 171.96 |
| 2160×3840 | 8,294,400 | 1450.84 | 1391.66 | 1480.12 | 174.92 |
| 280×3840 | 1,075,200 | 175.79 | 169.52 | 180.44 | 163.49 |
| 560×3840 | 2,150,400 | 361.60 | 358.68 | 386.46 | 168.15 |

### Scaling conclusion

Scaling is approximately linear in the number of pixels:

- 280×3840 → 560×3840: 2.00× pixels, approximately 2.06× time
- 1920×1080 → 3840×2160: 4.00× pixels, approximately 4.07× time
- Larger ROIs stabilize around 163–175 ms per million pixels

The small 960×540 case has relatively lower per-pixel cost due to fixed Python/function overhead and cache effects.

## 10. P2.18 Conclusion

Current post-P2.15/P2.17 bottlenecks are:

1. PQ OETF sqrt-LUT stage: **145.56 ms / 38.77%**
2. BT.1886 linearization: **105.46 ms / 28.09%**
3. Luminance curve LUT: **32.33 ms / 8.61%**

The transform scales approximately linearly with pixel count and runs as CPU NumPy/OpenBLAS work; no GPU path is active. The audit did not implement or recommend a concrete optimization, as required.
