## 1. Objective and constraints

The goal was to render five seconds of real Blade Runner HDR10 material through the new isolated FFmpeg 7.1.1 build and verify the infrastructure path:

```text
NVDEC/CUVID -> CUDA frames -> NVENC
```

The test did not modify production code, `transform.py`, `luminance.py`, `compose.py`, `render.py`, the P2.20 backend, or the existing FFmpeg installation. No additional components were installed. No commit or push was performed.

The final test used two variants:

- **Variant A — baseline:** NVDEC/CUVID decode directly to `hevc_nvenc`.
- **Variant B — CUDA path:** NVDEC/CUVID decode, CUDA-resident `scale_cuda`, then `hevc_nvenc`.

## 4. Final render commands

### Variant A — baseline NVDEC to NVENC

```powershell
"G:\Auto-OpenMatte-Sdr2hdr-converter\dev\ffmpeg-build\install\bin\ffmpeg.exe" -y -hide_banner -loglevel verbose -ss 2714.0 -hwaccel cuda -hwaccel_output_format cuda -c:v hevc_cuvid -i "G:\Filmy\Blade.Runner.2049.2017.2160p.UHD.Bluray.x265.HDR10.HEVC.DTS-HDMA.5.1-4K4U\Blade.Runner.2049.2017.UHD.BluRay.2160p.DDP.7.1.DV.HDR.x265-hallowed.mkv" -t 5 -map 0:v:0 -an -c:v hevc_nvenc -profile:v main10 -color_range tv -color_primaries bt2020 -color_trc smpte2084 -colorspace bt2020nc -fps_mode passthrough -map_metadata 0 -f matroska "G:\Auto-OpenMatte-Sdr2hdr-converter\test_output\P2711_real_baseline_5s.mkv"
```

### Variant B — CUDA-resident `scale_cuda` to NVENC

```powershell
"G:\Auto-OpenMatte-Sdr2hdr-converter\dev\ffmpeg-build\install\bin\ffmpeg.exe" -y -hide_banner -loglevel verbose -ss 2714.0 -hwaccel cuda -hwaccel_output_format cuda -c:v hevc_cuvid -i "G:\Filmy\Blade.Runner.2049.2017.2160p.UHD.Bluray.x265.HDR10.HEVC.DTS-HDMA.5.1-4K4U\Blade.Runner.2049.2017.UHD.BluRay.2160p.DDP.7.1.DV.HDR.x265-hallowed.mkv" -t 5 -map 0:v:0 -an -vf "scale_cuda=3840:1600" -c:v hevc_nvenc -profile:v main10 -color_range tv -color_primaries bt2020 -color_trc smpte2084 -colorspace bt2020nc -fps_mode passthrough -map_metadata 0 -f matroska "G:\Auto-OpenMatte-Sdr2hdr-converter\test_output\P2711_real_cuda_5s.mkv"
```

Important implementation detail: the final commands intentionally do **not** force `-pix_fmt p010le`. An earlier diagnostic attempt with that option forced an invalid CPU `auto_scale` path from CUDA frames and failed with `Function not implemented` (`-40`). Removing the explicit option allowed NVENC to consume the CUDA `p010le` frames context directly.

### Expected diagnostic warning

The first diagnostic attempt explicitly forced `-pix_fmt p010le`. That caused FFmpeg to insert a CPU `auto_scale` conversion from the CUDA frames context and fail with:

```text

Task finished with error code: -40 (Function not implemented)
```

This was corrected by removing explicit `-pix_fmt p010le` and using the actual source geometry. The failed diagnostic attempt is not part of the final PASS outputs.
